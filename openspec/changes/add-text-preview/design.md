## Goals / Non-Goals

**Goals:** Keep the existing no-preview code path recognizably intact; bound helper I/O, process count, memory and UI work; separate generic menu presentation from cache lookup; make each acceptance scenario independently executable.

**Non-Goals:** Images, ANSI styling, syntax highlighting, interactive subprocesses, command templates, preview caching, clipboard writes, history migration, fuzzy-algorithm repair/replacement, IPC servers, fzy/fzf integration, sandboxing arbitrary executables, or Xmonad changes. No additional runtime libraries. The optional shell helper may use existing POSIX shell/coreutils; GNU `stat` is already available in the target environment for ownership/mode checks.

## Decisions

### 1. Helper strategies

| Strategy | Responsiveness | Complexity | Security | Maintenance |
| --- | --- | --- | --- | --- |
| Direct per-selection child, stdin label and stdout text, nonblocking pipes polled alongside X | Cancellation and deadline do not wait for child; debounce avoids most churn | Two pipes, one child group, small explicit lifecycle | No shell interpolation or sensitive argv; close inherited descriptors | Recommended: familiar POSIX primitives, no protocol framing beyond EOF |
| Persistent helper/worker with framed requests and responses | Can be responsive, amortizes startup, but needs stale-response rejection and worker restart | Framing, buffering, request IDs, backpressure, supervision and restart rules | Long-lived process retains clipboard text; larger protocol/parser surface | Feasible but unjustified for local file reads and short-lived menus |
| Direct per-selection child with label in argv | Same event-loop approach, one fewer pipe | Slightly smaller | Exposes sensitive labels through process inspection; argument-size limits | Feasible but rejected for clipboard privacy |

Synchronous `popen()`/`system()` is not a responsive alternative: blocking reads and waits would freeze a keyboard-grabbing menu, and shell templates increase injection risk. A thread does not eliminate process cancellation/lifetime problems and introduces shared Xlib/state hazards. Select the first strategy.

### 2. Minimal public interface and scope

Keep `-P /absolute/executable` with no command arguments or format substitutions. The helper is trusted executable code, not clipboard data. Require an effective positive `-l`; reject horizontal preview instead of silently changing a caller's default layout. Validate this before opening/grabbing the menu. Missing/nonexecutable programs become a recoverable unavailable preview, not a menu-wide failure.

Pass precisely `sel->text` plus LF through stdin, then EOF. Labels already come from newline-delimited menu input. The helper has no arguments, stdout is raw text, stderr goes to `/dev/null`, and it inherits the user's environment (needed for `CM_DIR` etc.) without putting content in environment variables. Neither input text nor output is ever a command. Do not use `execvp`'s potential script fallback: use `execv` on the absolute path; executable scripts must supply a shebang. Trusted helpers may be shell scripts, but must treat all data as quoted data, never `eval` it.

Output states are fixed content-free `Loading`, `No preview`, `Unavailable`, `Timed out`, and `Truncated` indicators rendered inside the pane; no helper messages or sensitive stderr are surfaced. Status space is stable; all retained content remains scrollable. Successful empty output is `No preview`. An ordinary nonzero helper exit without detected overflow discards incomplete output as unavailable. Detecting an additional byte beyond 65536 bytes latches an overflow terminal cause: retain a safely renderable prefix marked truncated and cancel the producer. Its subsequent SIGKILL/signalled/nonzero status must not overwrite Truncated with Unavailable or Timed out. A superseding selection still discards that result. Exactly 65536 bytes followed by EOF and successful process completion within the helper deadline is successful, not truncated.

Checkpoint 4B clarification, explicitly approved by the user: keep the existing footer geometry. With `-l 1`, Truncated occupies the only body row and has no text viewport; at least two body rows are required to read truncated content. Successful single-row previews remain scrollable. This is the sole exception to retained-text reachability, not authorization to redesign the input row or pane.

### 3. Nonblocking event-loop and lifecycle

Preview state remains file-local in `dmenu.c`: current requested item/generation, pending selection/debounce time, child PID/process-group identity, pipe fds and stdin offset, monotonic deadline, bounded output and rendered row offsets, scroll offset, and result state. No generic job abstraction or background service.

- Without `-P`, keep blocking X event handling and existing drawing/matching paths; no buffer allocation, poll timer, fork or preview fd.
- With `-P`, drain queued X events with `XPending()` before sleeping, processing only a bounded batch per iteration so a key flood cannot starve I/O/deadlines. Use `poll()` on `ConnectionNumber(dpy)`, the nonblocking stdout pipe, and stdin write readiness while bytes remain. Flush X requests before sleeping; Xlib can already have buffered events even if its fd is not readable.
- Reconcile `sel` centrally before the next draw/sleep, covering initial setup, keyboard editing/navigation and paste rather than adding a helper call to each selection assignment. Compare item identity, not label string: duplicate text can be separate items. Selection changes clear prior content/scroll immediately and reset a 40 ms monotonic debounce. Empty selection cancels without replacement.
- On launch, fork once. Establish a dedicated process group in child and parent to avoid the setpgid race. Connect child stdin/stdout to pipes, stderr to `/dev/null`; close both unused ends, X connection fd and all unrelated inherited fds before `execv`. Parent uses nonblocking I/O, close-on-exec descriptors, and bounded writes even for huge original labels. Handle `EINTR`, `EAGAIN`, short writes, early stdin close, and `SIGPIPE` without killing dmenu; reset SIGPIPE disposition for the child.
- Read at most 4 KiB per loop turn into at most 65536 raw bytes plus terminator; after filling that buffer, use a one-byte overflow probe rather than allocating more. Incremental UTF-8/display conversion and row storage have explicit worst-case caps proportional to raw bytes, including control replacement/tab expansion. Do not allocate by untrusted reported lengths or build rows quadratically for a huge line. Deadline and X handling run between chunks.
- Each request has a 1000 ms monotonic deadline measured from launch, covering helper execution, stdin delivery, stdout collection and process completion. EOF alone is not success: collection succeeds only after EOF and successful child exit within this deadline. A child exiting while descendants retain stdout remains subject to the same deadline; so does a child closing stdout but remaining alive. Text sanitization/layout is a separate phase governed by per-loop work budgets, not by this deadline; finishing that phase after launch + 1000 ms does not turn a completed collection result into a timeout. No `waitpid(...,0)` or blocking helper read/write in the event loop.
- Selection cancellation, timeout, detected overflow or protocol/I/O failure closes request pipes and sends SIGKILL to the owned helper group. Send the signal immediately rather than implementing a grace-period escalation, but never equate dispatch with instantaneous process disappearance. Keep only the newest pending selection; do not launch a replacement until the old direct child has been reaped with `waitpid(...,WNOHANG)`. There is one active request slot; already-signalled cooperative descendants may still be terminating. Poll no later than every 20 ms while a child needs reaping; otherwise use the nearest deadline/debounce or block indefinitely when idle.
- Results carry generation ownership; old bytes can never be published for a newer item. Do not depend solely on fd numbers, which can be reused. Clear group ownership after teardown and never signal an unrelated or already-released pgid.
- Exit cleanup first issues the keyboard ungrab and flushes that X request, then closes pipes, sends SIGKILL to the owned group and reaps only already-waitable children nonblocking before freeing resources. Never wait for helper termination during menu exit. If a killed process is not yet waitable, parent exit hands final reaping to the OS. While dmenu remains running, reap each direct child before reusing its request slot. Controlled tests separately observe eventual termination of cooperative group members for up to 2000 ms from SIGKILL dispatch; this is an observation window under normal test scheduling, not a synchronous exit wait or an instantaneous-disappearance guarantee.

This is process containment for cooperative trusted helpers, not a malicious-code sandbox. Descendants deliberately escaping the process group and uninterruptible kernel I/O cannot be absolutely bounded by these mechanisms; do not claim otherwise. One in-flight slot prevents navigation from spawning unbounded replacements if a child is stuck in kernel I/O.

Apply the same nonblocking teardown and eventual-termination observation to cancellation, timeout, overflow, ordinary failure, successful completion with remaining cooperative descendants, window destruction and menu exit. Tests must not assert that a signalled group is already absent when the handler or menu returns. Descendants intentionally leaving the group are outside containment guarantees; an optional adversarial fixture for that case must be cleaned up by the external test harness, not counted as a menu guarantee.

### 4. Geometry and text

Keep one X window and the existing normal/selected/output schemes. In preview mode preserve the requested `-l` count before stdin's item-count clamp. After choosing monitor/parent dimensions, clamp body rows to fit the screen/parent, retain at least one row plus input, and reject physically unreadable geometry. Compute bottom placement after height is finalized. Use signed checked intermediates before unsigned drawing dimensions; split the available width approximately 2/5 and 3/5 with a one-pixel divider, ensuring both panes have padding and at least one glyph of usable width.

The full-width input/prompt row is unchanged. Body item rows start at x=0; use the existing `drawitem()` with left-pane width, retaining selection/output colors and linked-list paging. Right-pane rendering never mutates item strings, search strings, or fuzzy distances. Empty/missing preview and zero matches do not shrink the body.

Preprocess only preview bytes: LF creates rows including blank lines; tabs expand to four-column stops; invalid UTF-8 and C0/C1/DEL controls become U+FFFD. CR is inert replacement, not cursor movement; ESC is not ANSI. Embedded NUL must not end the byte buffer early. Use libc multibyte conversion with explicit byte lengths/state or an equivalently small checked scanner, then the existing font metrics/rendering for valid display text. UTF-8 codepoints, not bytes, are wrapping boundaries; full grapheme/shaping behavior is limited by existing Xft rendering. Soft-wrap at pixel width, guaranteeing consumption even when one glyph exceeds the pane. Build row offsets once per completed bounded result; draw only visible rows. Avoid repeatedly measuring an ever-growing prefix. No horizontal scrolling is needed because long lines wrap.

Text preparation is also scheduled work, not an unbounded completion callback: sanitize and measure at most 256 codepoints per event-loop turn, then return to X events/deadlines. A selection change cancels pending row preparation just like helper output. Publish the completed current-generation layout only when ready; retain the fixed loading state meanwhile. Allow at most four display bytes per retained raw byte plus a terminator, and at most one row-offset entry per display byte plus one, using overflow-checked size arithmetic. These ceilings bound control/tab expansion and narrow-pane wrapping without assuming the raw cap alone bounds rendering latency.

While row preparation remains pending, use a zero poll timeout after servicing X and helper work so progress does not depend on another keypress. Stop these wakeups as soon as the result is ready or cancelled.

Intercept Alt-Up/Down, Alt-PageUp/PageDown and Alt-Home/End before the existing Mod1 translation, only with preview enabled. They alter preview row offset only. Keep existing Ctrl keys, plain paging, cursor editing, and Alt-letter navigation intact. Reset scroll when selection changes, not on Expose or cursor-only redraws.

### 5. Small standalone clipmenu helper

Use a separate POSIX shell script, `clipmenu-preview`, with ordinary existing coreutils, not a dmenu clipboard mode. Read one LF-delimited label with `IFS= read -r`, preserving whitespace/backslashes. Resolve defaults exactly as installed launcher (unset, not `:-` semantics); validate USER is a nonempty single safe path component. Resolve only `clipmenu.6.$USER`, not arbitrary paths from the label. Compute `printf '%s\n' "$label" | cksum`, retain both numeric output fields, and quote the entire filename. No need to read, sort or deduplicate `line_cache`: the launcher already supplied the original label, and its checksum lookup does not consult the index again.

Before opening, reject a symlinked final cache directory, verify directory ownership against the current uid and mode has no group/other access (GNU `stat`, `id`, or equivalent existing tools), and reject symlinked/nonregular/unreadable payloads. Fail closed without content diagnostics. Stream payload with quoted `cat -- "$file"`; do not capture payload into a variable. This preserves all stored newlines and lets dmenu enforce the output cap. No xsel, daemon calls, cache writes, locks, temp content files or new dependencies.

Path checks in a shell script are not atomic against a same-UID adversary. Trust the caller-selected ancestor directories and the private owned final cache directory, as the existing clipboard stack does; same-UID hostile mutation remains outside the boundary. Replacing this with `openat`/`O_NOFOLLOW` in a compiled helper would add code and packaging for a threat that the same-UID clipboard daemon cannot itself resist. A missing/vacuumed file is simply unavailable. Concurrent rewrite may expose a transient prefix; do not lock or change the daemon to promise snapshot consistency it does not provide.

Integration example for later approval, not executed in this session:

```sh
CM_LAUNCHER=/absolute/path/to/new/dmenu \
  clipmenu -i -l 12 -p Clipboard -P /absolute/path/to/clipmenu-preview
```

The selected label still flows untouched back to clipmenu. The helper is an optional separately installed file, not a change to existing dmenu launch scripts or to PATH/cache contents. Include it in the distribution's explicit file list if shipped; document explicit user-local installation rather than silently adding it to generic `make install`.

## Risks / Trade-offs

- [Lifecycle correctness is the largest new burden] → One child slot, direct execution, monotonic deadlines, bounded poll/read work and focused adversarial lifecycle checks; avoid threads/persistent protocols. Expected maintenance is localized but nontrivial: subprocess/poll logic and UTF-8 wrapping are materially more complex than a geometry-only patch.
- [A finite cap cannot show literally unlimited full text] → Read complete payloads up to 64 KiB; explicitly mark longer previews truncated. Original data/restoration remain untouched. A request for larger text is a limit decision, not an excuse to allocate without bounds.
- [Preview cannot be a sandbox or confidential against same-UID inspection] → Trusted absolute helper, no shell data evaluation, no content argv/stderr/logging/temp files; document inherited environment and process-group limits.
- [New rendering could regress no-preview layout or fuzzy selection] → Keep opt-in branches, compare against an isolated pre-change build for all existing modes and selection/output semantics.
- [OpenBSD pledge currently allows only stdio/rpath] → If retaining that build target, conditionally add the required proc/exec promises only for preview mode and verify on OpenBSD when available; do not weaken the no-preview promises. Linux is the deployment acceptance platform; disclose untested portability, never silently ship a knowingly nonfunctional guarded path.
- [Font fallback and malformed data can amplify work] → Bounded raw/display/row allocations, linear or bounded-amortized preprocessing, finite per-loop work, UTF-8 boundary tests and sanitizers. Reuse existing Xft behavior rather than promise full Unicode grapheme shaping.
- [clipmenu's label checksums collide and history mutates] → Match its exact lookup and expose unavailable/transient state, never promise stronger identity guarantees or change storage.

These servers are currently absent; arrange them before the early UI checkpoint. After baseline/CLI and before subprocess infrastructure, use synthetic preview text and record a screenshot plus keyboard-navigation results proving readable text, selected highlight, 40/60 pane proportions and stable layout through selection/short-list/zero-match transitions. This checkpoint is incremental, not a replacement for final acceptance. Capture synthetic-only evidence and exact stdout/exit status; do not collect private-history screenshots.

5. **Failure/time bounds:** Synthetic executable helpers read slowly/not at all, exit nonzero after data, hang, close stdout then hang, delay an old selection, write without bound, emit stderr, fork a child keeping stdout, or exit immediately. Verify UI input/cancel and keyboard release on exit within a 100 ms target under an otherwise idle isolated X server, debounce near 40 ms, and the 1000 ms deadline across execution/input/output/process completion (allow scheduler tolerance). Check no stale result, bounded processes/fds and no content diagnostics. Separately observe cooperative-group termination for up to 2000 ms from SIGKILL dispatch without making menu exit wait for it; escaping descendants are outside this assertion. Exercise 1-4 byte UTF-8 split across reads/cap, malformed/truncated sequences, embedded NUL, CR/ESC/C0/C1/DEL, tabs, blank/trailing lines, combining marks, CJK/emoji and one maximum-size long line. A completed helper whose preparation finishes after launch + 1000 ms must not time out. Emitted labels stay unchanged.
7. **clipmenu helper and restoration:** Use private temporary fixture directories only, explicit `CM_DIR` and synthetic `line_cache`/payload files. Compare helper checksum names to installed Bash here-string computation, test empty/unset env precedence, duplicates/collisions, malicious literal labels, mode/owner/symlink/FIFO checks, missing/vacuumed payload and byte-exact multiline/trailing-newline stdout. 8. **Memory/resources:** Build with ASan/UBSan and debug symbols, run the isolated scenarios, and use Valgrind when available for leak/error checks (not currently installed). Intentional group escape is not a containment claim; external fixtures must clean up their own escapees. Separate pre-existing upstream issues from new regressions without widening scope into unrelated repairs.
